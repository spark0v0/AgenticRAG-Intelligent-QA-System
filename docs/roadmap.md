# P2 需求与实现建议

本轮范围为问答工作台与执行观察，不扩展工作流编辑器、权限平台、多租户或计费。

| 功能 | 当前接口缺口 | 建议最小增量 | 前置风险 |
| --- | --- | --- | --- |
| 知识库进一步扩展 | 本轮已完成 TXT/Markdown/文本 PDF、作业状态、重试/取消/删除和证据联动，详见 knowledge-workbench.md | 后续按实际需求考虑 OCR、更多格式和规模优化 | 当前单进程、本地规模；不默认增加复杂任务平台 |
| 工具动态启停/编辑 | 当前仅 list/schema | PATCH /tools/{id}，持久配置加版本号；运行任务固定工具快照 | 正在运行任务的一致性、协议参数验证、不能任意执行命令 |
| 更多供应商适配 | 已完成 OpenAI 兼容/DeepSeek/Ollama/Xinference 配置写入、模型列表检查 | 后续按需求增加非兼容协议及本机流式适配 | Windows 用户级加密不等于跨用户密钥管理，公网部署仍需认证 |
| 复杂知识图谱 | 当前配置式关系查询 | 先定义节点/关系读接口、分页与证据来源，再评估图编辑 | 无真实图数据库/管理服务，不能把配置示例称完整图谱平台 |
| Dify 插件发布 | 只有 Python 工具包装 | 按实际 Dify 版本补 manifest、SDK、鉴权和发布验证 | 外部环境依赖，不能以文件存在作为发布成功证据 |

工程后续：会话消息分页与媒体文件存储、多 worker 任务协调、更多供应方异步取消、严格图片内容解码、完整依赖锁与安全更新。运行列表已分页，选中活动运行支持自动刷新；没有扩展为工作流编辑器。先针对测量到的瓶颈再决定动态高度虚拟列表。

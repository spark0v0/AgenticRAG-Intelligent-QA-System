# P2 需求与实现建议

本轮范围为问答工作台与执行观察，不扩展工作流编辑器、权限平台、多租户或计费。

| 功能 | 当前接口缺口 | 建议最小增量 | 前置风险 |
| --- | --- | --- | --- |
| 知识库上传/解析/索引/删除 | 无上传、文档清单、作业状态、删除 API | POST /documents、GET /documents、GET /index-jobs/{id}、DELETE /documents/{id}；先支持一种文档类型 | 文件路径隔离、大小限制、解析沙箱、原文与 Chroma chunk 对应、失败回滚 |
| 工具动态启停/编辑 | 当前仅 list/schema | PATCH /tools/{id}，持久配置加版本号；运行任务固定工具快照 | 正在运行任务的一致性、协议参数验证、不能任意执行命令 |
| 模型配置写入 | 当前仅读取后端档案 | POST/PATCH /model-profiles、单独连接验证接口 | 凭据只写后端，响应脱敏，验证调用成本明确 |
| 复杂知识图谱 | 当前配置式关系查询 | 先定义节点/关系读接口、分页与证据来源，再评估图编辑 | 无真实图数据库/管理服务，不能把配置示例称完整图谱平台 |
| Dify 插件发布 | 只有 Python 工具包装 | 按实际 Dify 版本补 manifest、SDK、鉴权和发布验证 | 外部环境依赖，不能以文件存在作为发布成功证据 |

工程后续：历史分页与媒体文件存储、跨页运行状态刷新、多 worker 任务协调、更多供应方异步取消、严格图片内容解码、完整依赖锁与安全更新。先针对测量到的瓶颈再决定动态高度虚拟列表。

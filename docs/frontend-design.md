# 前端设计说明

## 设计目标

前端提供问答、知识库、供应商配置和运行分析入口。接口适配、共享状态、可复用逻辑与组件视图分开组织；服务端负责执行结果与持久化，前端负责交互状态、事件消费和数据展示。

## 选型

| 技术 | 对应需求与取舍 |
| --- | --- |
| Vue 3 / script setup / Composition API | 按业务职责组合状态、展示与资源生命周期 |
| TypeScript | SessionSummary、Message、QueryRequest/Result、Source、ToolCall、ExecutionEvent 判别联合 |
| Vite / Vue Router | 独立开发代理、生产构建；页面路由懒加载 |
| Pinia | 多会话、当前会话、处理模式、模型、运行状态和执行记录 |
| Element Plus | 复用表单、输入、选择器、数字输入、开关、对话框及移除确认；供应商生命周期、运行分析、会话和流消费由本项目实现 |
| Fetch / ReadableStream | POST 同时提交问题与图片，无需 EventSource 的额外任务创建连接 |
| markdown-it / DOMPurify / highlight.js | Markdown 解析、安全净化和有限语言高亮 |
| SCSS / CSS 变量 / @lucide/vue | 响应式样式、主题与维护中的图标库；旧 lucide-vue-next 安装时已被标记 deprecated，改用官方后继包 |
| SQLite | 标准库即可支持事务、唯一约束和运行历史；Chroma 保留检索职责 |
| Vitest / Vue Test Utils / Playwright | 流与状态逻辑、Markdown 组件及少量完整业务冒烟 |

不用 Vue Flow：当前需求是执行记录，不是工作流编辑，时间线可直接表达真实节点与多次生成。使用已有 npm 锁文件，避免双包管理器。以隔离长会话测量作为基线，不因消息数量预先引入虚拟列表或声称优化百分比。

## 状态所有权

- 服务端权威数据：最终答案、来源、工具结果、评审、运行终态与阶段起止记录。客户端 completed 事件替换整条回答，刷新结果与最终记录一致。
- Pinia 共享状态：处理模式、模型选择、会话缓存、当前 ID、每会话草稿/附件/消息/事件。busy 和所选来源等由 computed 派生。
- 非响应式资源：按 run_id 索引的 AbortController、文本缓冲与 timer，避免代理浏览器资源。
- 组件局部状态：搜索条件、详情 tab、导航展开、文件读取、滚动跟随。
- localStorage：主题、所选模型/处理模式、当前真实会话 ID；不保存 Key、图片或回答文本。启动时移除旧模式状态，只迁移旧真实会话指针，模型不存在时使用后端默认档案。文本草稿与所选知识库/模型/模式延迟 250ms 写入本机浏览器，最多保留 20 份、30 天，每份最多 50,000 字符；不保存图片或回答。失败/取消的已提交输入仍可从后端恢复。

运行转换：idle → submitting；只有收到 delta 才进入 streaming；完整结果模式维持 submitting；完成、错误、取消分别进入 success/error/cancelled。再次发送建立全新 run_id。提交互斥绑定会话，不阻止其他会话运行。

## 生命周期和竞态

1. 发送前生成 session_id、run_id，快照请求参数并创建该轮用户/助手消息。禁止同一会话重复发送。
2. SSE envelope 校验 run_id/session_id；seq 去重。异步闭包始终写所属 conversation，不读取“当前会话”作为结果目标。
3. 切换会话保留后台执行。未完成会话立即加入侧栏，可返回停止；历史读取用 AbortController 与版本号丢弃旧响应。
4. 增量 60ms 批量追加；每次 answer_start 清空上一生成轮草稿。completed 采用后端最终回答与来源，防止 Critic 修订拼接。
5. 取消立即中断本地读取，并并行请求 run 取消接口，显示“停止中”。输入锁保留至确认完成或 5 秒确认超时。若完成抢先提交，以取消接口返回的已保存 success 结果为准。确认失败提示刷新核对，不声称供应方停止计算。
6. finally 只清理本 run 的资源，并检查 activeRun 是否仍是该 run。失败/取消恢复输入；禁止自动重放请求。
7. App 卸载清理请求；图片 FileReader 在切换会话、组件卸载或同批读取失败时 abort，版本号阻止晚到结果修改附件和读取状态。采用 data URL 直接预览，无对象 URL 需要撤销，图片内容只序列化进当前请求与后端附件历史。

## 渲染与交互

Markdown 禁用原始 HTML，再经 DOMPurify 净化；禁止远程图片/iframe/style/form，避免答案中的追踪图片。安全来源链接只接受 http/https，新页面链接带 noopener/noreferrer。流动草稿暂缓代码高亮，终态后只高亮注册的 JS、TS、Python、JSON、CSS 语言。

路由与执行详情懒加载。用户向上阅读时停止滚动跟随，新增文本不抢位置；回到底部重新跟随。输入处理 isComposing 与 229，Shift+Enter 保留换行。图片每轮最多 4 张，每张不超过 4MiB，类型 PNG/JPEG/WebP/GIF，与 API schema 一致。服务端还校验 MIME/data URL 与 base64 长度；尚未进行完整图片内容解码检测。

时间线使用实际 stage_id 聚合开始/结束事件，每个生成轮保留独立 round。工具注册状态与本次执行状态分开；真实 duration_ms 来自后端 perf_counter，不从一个时间戳推测。仅显示已发生节点，未发生节点不伪装成等待流程。事件是系统执行摘要，不展示或虚构模型内部思维链。

## 阅读与详情交互

Markdown 围栏代码块由独立标题栏与横向滚动的代码区组成。语言标记经过 HTML 转义，复制操作只读取该代码块的文字，并在原按钮附近反馈；剪贴板权限拒绝时提示手动选择。复制请求使用版本号和卸载标记，组件销毁后不再更新反馈或创建定时器。外链在渲染时设置新窗口及 `noopener noreferrer`，键盘访问与鼠标访问采用相同规则。

输入区通过 `useTextareaSize` 随草稿和可用宽度调整高度，保留 CSS 控制的最小高度、180px 上限和内部滚动；离页清理 ResizeObserver 与动画帧。执行详情在桌面使用侧栏，1000px 及以下复用 Element Plus 抽屉的遮罩、焦点约束和嵌套弹层行为；关闭返回触发位置，跨布局断点或切换会话时收起，避免遮罩残留或误读其他会话。详情显示对应问题摘要，仅按相同 run_id 关联。

执行详情与运行分析共用 `useTabs`，只将当前标签加入 Tab 顺序，方向键循环切换、Home / End 跳至首尾；标签与内容通过稳定 ID 关联。原文证据仍使用独立抽屉，关闭原文后返回来源按钮，继续关闭执行详情才返回回答中的引用。

## 性能边界

当前小规模会话搜索在内存过滤；后端历史接口会读取全部消息，暂不分页。长会话夹具包含 60 条消息（30 条带长文本与 60 行代码的回答）。结果写入 `frontend/test-results/evidence/history-metrics.json`：historyReadyMs 包含导航和资源加载；vueDomMs 从历史 JSON 解析完成计到 Markdown DOM 提交；renderWindowMs 再等待两帧，包含 Vue 更新、布局与帧调度；inputMs 包含自动化操作开销；scrollFrameMs 是滚动设置至两帧后的浏览器时间。这些值不是模型耗时，也不是单独的 markdown-it 解析时间。真实模型与夹具数据分开记录，构建体积以当前 Vite 输出为准。

## 主题与布局

界面参考 [Linux DO](https://linux.do/) 的内容优先排版：白色背景、中性灰分隔、清晰的文字层级和列表结构。顶部通栏展示品牌与当前位置，左侧导航与会话记录使用紧凑行布局；蓝色主要用于链接、选中状态及主操作，错误与警告保留独立语义颜色。深色主题使用中性灰阶。

英文和数字使用本地 Inter 变量字体，中文使用 Noto Sans SC 变量字体；中文正文与输入为 16px，导航为 15px，操作和辅助信息主要为 13–14px。Noto 通过固定版本的 Fontsource 包提供 unicode-range 分片，Inter 只打包 Latin 子集。字体随应用构建，运行时不请求外部字体服务；font-display: swap 和系统字体负责加载期间及失败回退。两个字体的 OFL 许可证随 public/fonts 分发。完整中文字体资源增加构建目录体积，浏览器只加载页面实际字符涉及的分片。

问答首页采用左对齐标题、检索范围栏、输入区和建议问题列表。建议问题只填入草稿并聚焦，不直接发送；进入对话后输入区停靠底部，回答以分隔线和角色信息形成连续阅读区。回到底部按钮处于独立布局行，避免依赖输入框的固定高度。窄屏收起导航，打开后聚焦导航，Escape 收起并返回菜单按钮；320px 宽度下检索范围排列成两列，模式与模型选择分行，避免过度截断。

知识库以横向分类标签和完整宽度的文档表格呈现；切换、创建知识库后，选中分组滚动到可见位置。文件类型、当前可检索状态与后台索引任务分开显示，失败和需要重建的文档不会仅凭“任务完成”呈现可检索状态。文档表格在自身容器内横向滚动。工具中心采用分隔列表，宽屏状态在右侧、窄屏换行；运行分析保留记录列表、真实耗时瀑布与证据详情。

窄屏导航展开时以对话框语义呈现，背景使用 `inert` 暂停交互，Tab / Shift+Tab 在侧栏内循环；Escape 关闭后返回菜单按钮，选择导航后聚焦主内容。点击当前路由也会收起导航，切换到桌面宽度会清理遮罩状态。键盘用户可使用“跳到主要内容”跳过导航；隐藏图片输入不参与 Tab 顺序。

历史列表刷新拥有独立的加载和错误状态，不将列表请求失败显示为整个服务断线；搜索支持清空并保留输入焦点。知识库创建错误在弹窗内显示并聚焦，保留名称与检索方式；创建成功后直接采用 POST 返回的资料库，避免将后续列表刷新失败当成创建失败。文档列表区分加载、读取错误、空库与筛选无结果，清除筛选后返回搜索框。

圆角控制在 4–8px，避免多层卡片和装饰性欢迎图；交互动效仅用于悬停、焦点和面板展开，尊重 reduced-motion。没有新增 UI 框架或业务数据。

`styles/main.scss` 只组织导入；`_tokens.scss` 定义亮暗色语义变量及 Element Plus 映射，`_base.scss` 管基础控件，`_shell.scss` 管导航，`_chat.scss`、`_providers.scss`、`_runs.scss`、`_catalog.scss` 管业务样式。已合并相同选择器与断点内的重复声明，移除旧 `workspace.scss`；修改直接回到所属模块，不新增覆盖文件。图标统一使用 Lucide，手机端主要操作目标为 44px。主题对文字、输入边框、错误背景和按钮前景分别定义，避免深色主题仍套用浅色按钮文字。

没有新增 UI 框架或图编辑依赖。Element Plus 负责成熟表单与弹窗的基础交互，业务组件负责配置映射、错误恢复与提交状态。常用问题只填入草稿。供应商检测仅请求模型列表，`check_ok` 不等于生成成功；系统页 `connection_verified` 仍只来自本次进程中完成的真实回答。

## 新页面的状态边界

供应商数据和表单草稿属于页面局部状态，不进入 Pinia/localStorage。Key 仅停留在表单内存与保存请求中，保存/关闭后清空；已保存 Key 只返回 has_key。后端更改配置后刷新共享模型列表，不重建正在运行的问答系统。每个运行仍使用已经捕获的配置字典；旧配置的回答成功不会把新配置误标为已验证。

ProviderForm 拥有独立保存状态与 AbortController；ElForm 处理 URL、模型 ID、重复模型和数值字段校验。`ApiError` 保留 HTTP 状态、字段路径和安全消息，不渲染 Pydantic input/ctx 或任意可能包含凭据的校验消息。保存失败保留输入，错误摘要可聚焦对应字段；留空保留 Key，与清除开关互斥。供应商列表读取有独立版本号，离页中止请求并阻止旧响应更新；中断保存只代表浏览器结束等待，不能证明服务器没有提交，因此不会自动重放。

连接检查必须判断响应 `ok`，失败走错误提示并清空上一次发现的模型。`has_key`、持久化 `check_ok`（模型列表接口）与 `connection_verified`（当前后端进程完成过真实生成）分别展示；后端重启后生成验证状态可能恢复为未验证，历史回答仍保留。

运行分析通过 `/runs` 分页查询摘要，通过 `/runs/{id}` 获取单轮详情；URL query 保存所选 run，支持刷新和从消息跳转。搜索防抖 250ms；列表和详情各有 AbortController/版本号，旧响应不能覆盖新选择。进行中的选中运行每 2 秒刷新，离页清理轮询和连接。瀑布位置来自真实 started_at，条长来自 duration_ms；小于一个像素的节点设最小可见宽度，数字耗时仍是真实值。未结束节点不估造耗时，视图不重放 token。

窄屏进入 `/runs` 先显示列表；选择记录或直接带 run 参数访问才展开详情。返回列表保留搜索、分页、筛选和选择，并将键盘焦点还给选中记录。运行与筛选条件通过 URL 恢复。没有结束时间或耗时的记录显示「未记录」，不会以浏览器计时替代后端数据。

来源展示后端证据。Generator 已为模型提供 `source_map` 与 `[S1]` 引用约定，仅将回答里明确出现、且存在于最终 source_map 的编号渲染为按钮。使用 markdown-it 行内规则处理，跳过代码与已有链接；DOMPurify 仍在渲染后净化。点击后传递所属 run_id/source_id，展开来源、滚动并聚焦证据。旧记录无映射时保持普通文本和独立来源列表，不根据句子或数组下标猜测归属。流式草稿未取得最终映射时不提供引用跳转。

节点期间的工具通过时间区间归属，只称「节点期间的工具调用」，不捏造父子 ID。导出是单轮已脱敏服务端记录，仍包含问题、回答和证据，需自行确认是否适合分享。

## 请求选项恢复与知识库反馈

每个会话保存当前知识库、范围、模式和模型选择；切换会话恢复该会话选项，不改变后台运行已捕获的请求。后端在创建 run 时保存独立 request 快照，前端刷新后以最近一轮快照初始化选项；失败/取消同时恢复问题和附件。再次发送采用输入区当时可见的选项，用户可先修改知识库或模型，不自动重试。成功回答的 retrieval_plan 是实际执行结果，不再承担请求选项的主要存储职责。

旧运行缺少有效快照时，参考最近成功回答的检索范围并提示用户确认模式、模型和知识库；没有可恢复信息则使用自动范围和当前模型偏好。已记录但被删除的库保留原 ID，显示不可用并由服务端拒绝该范围，不能静默改用项目内置资料。已删除的模型同样保留选择并提示重新配置。尚未发送的文本草稿与选项保存在当前浏览器，最多 20 条、保留 30 天；图片附件不写入浏览器存储。

ActiveRun 拥有本轮 AbortController、60ms 文本批次和定时器；集中同步消息与会话终态，释放时只清理对应 activeRun。晚到的旧运行取消确认可修正旧消息，但不能覆盖新运行的状态。60ms 批量更新与终态高亮是已有策略，此次只整理职责。

文件上传仅显示上传中，不显示未经测量的字节百分比。文档当前可检索状态和后台任务状态分别展示；配置指纹不符时显示需要重建。操作反馈捕获发起时的知识库和文件名，切库后隐藏不属于当前库的结果；删除整库的反馈明确标注原库名称。删除文档的确认框返回稳定搜索框，避免焦点落到已删除的行。文档轮询和资料库删除轮询独立清理，离页后不重新发请求。

## 会话与阅读交互

- 会话列表使用服务端搜索与摘要分页，首次 30 条；重命名/置顶响应更新当前列表，删除需确认且服务端拒绝删除活动会话。
- 导出 Markdown 包含问题、回答、证据文字及未完成轮次的状态，不包含图片数据、供应商配置或密钥。
- 运行详情读取错误与列表错误分开处理；活动记录读取失败最多延迟 2/4/8 秒重试，显示最后更新时间。只重试 GET，不重放生成请求。
- “回到会话”固定目标 ID；切换运行或离页使关联读取失效。运行搜索/状态/页码与知识库 ID/文档筛选通过 URL 恢复。
- `PdfReader.vue` 在用户展开原文时才加载。每次只绘制一页，旧渲染任务在翻页/缩放时取消；关闭抽屉销毁 Worker、文档和 ResizeObserver。文字证据继续独立提供，不依赖 Canvas 可访问性；目前不提供全文选择或逐句高亮。
- PDF Worker、CMap、字体和 WASM 均由本机提供，不使用第三方 CDN。辅助文件由 `predev/prebuild` 从锁定依赖复制，生成目录不入 Git。
- `api.generated.ts` 从 FastAPI 会话响应模型生成并在 CI 检查漂移。其余接口与 SSE 仍使用现有显式类型、边界检查，后续按模块扩展响应模型。

## 检索预览与对比

`RetrievalPreview.vue` 拥有输入、请求控制器及结果；知识库页面仅传入当前资料库。单模式与对比共用已有证据抽屉。结果记录发起时的问题与库名，输入编辑不会改写已展示结果的含义；切库同步取消读取并清空结果，晚到响应按控制器与库 ID 双重检查后才能更新状态。停止等待后焦点返回问题输入框。

桌面三列对齐展示关键词、语义与融合，窄屏顺序排列。由 chunk_id 分配相同片段编号，显示原始分数、两路入选排名及各自空/失败/不可用状态。共用阶段耗时放在可展开说明中，不以浏览器等待时间替代后端记录，不以排名分数推断回答质量。

# AgenticRAG 要求对照与改进

## 结论

项目具备真实检索增强生成与工具执行，但没有完全满足原研究要求。五类智能体是职责分离的执行模块，不是五个独立训练的模型，也不需要每个节点都调用大模型。

Agentic 体现在选择流程、复杂问题生成检索子问题、选择数据源、预算内重检索与引用问题修订。RAG 体现在检索文档/外部摘要、筛选证据、证据与编号进入提示词、最终回答和来源共同持久化。搜索有数据源选择、查询变体、工具结果和失败记录；问答有真实模型生成、多轮历史和流式交互。

## 慢回复原因与本轮修改

原自动路径先等模型分类，再等模型选工具，之后才检索和生成。复杂任务将独立检索串行执行；后两轮查询改写可能相同；按回答长度和条目格式打分容易造成无效重写；联网请求顺序执行且失败会丢掉已有结果。这是代码路径上的额外等待，不能据此断言占真实耗时的百分比。

- Router：明确命令/检索范围跳过模型分类，修复 URL 中 `/`、单词中 `hi` 的误判；模糊请求才有超时地调用分类。
- Planner：深度路径生成结构化子问题并实际用于检索；独立问题并行，生成依赖证据；失败在 metadata 标明降级来源。
- Retriever：默认策略选工具，保留 `tool_selection: model`。不默认调用示例 MCP，也不因“分析”自动联网。请求去重、限制轮次、记录停止原因。
- 中文检索：重叠二元词元、预计算 BM25 统计、RRF 双路排名融合；过滤零重合哈希碰撞，不凭 README 文件名加分。仍不是语义嵌入。
- Generator：选择查询相关原句，而非只取前 480 字；证据总量受 max_context_chars 限制，source_map 保存实际传入模型的片段；历史有字符预算。
- 查询理解：检索前移除常见的“根据本地文档、用一句话、引用来源”等输出格式指令，生成仍保留原始问题；模型提示词优先遵守用户长度要求。该最后修补离线通过，未再进行付费复测。
- Critic：检查不存在的编号、正文缺引用、无证据未说明边界；不按长度催促扩写，最多修订一次。剩余问题返回前端，不伪称通过事实核验。
- 联网：并行异步请求，单源失败保留另一源结果；engine_errors 记录失败来源，取消可关闭 HTTP 连接。

## 使用与计时

先添加自己的供应商和模型。输入框选择「本地知识」并问“AgenticRAG 如何保存会话历史？请标注来源”，查看本地 RAG、来源片段和执行详情。选择「联网搜索」查询百科实体；选择「本地 + 联网」并行检索两类来源，不保证都命中。选择「深度分析」提出比较问题，检查 Planner 的 search_queries 和实际工具调用。快速回答跳过检索；图片按模型能力进入视觉路径。

执行详情显示查询、工具、停止原因及时间。first_delta_ms 是后端收到首个供应方文本增量距运行开始的时间，包含路由、检索与网络等待；total_ms 截至最终结果构建。两者都不是纯模型 TTFT、Vue 渲染时间或完整网络往返。

## 兼容与证据

新增 context.search_scope：auto / local / web / all，省略保持自动模式。结果增加 evaluation、timing 及 retrieval_plan 扩展，旧记录缺字段不显示。SSE 事件名与终态保持，修订仍按 generation 替换草稿。

分词版本由 3 升至 4，首次启动按 manifest 重建衍生 Chroma 索引，原始文档、SQLite 和供应商库不删除。无 SQLite schema 变更、无新增依赖、无凭据恢复、无演示模式。

本轮验证见 verification.md。用户在工作期间自行添加供应商后，完成一次真实本地问答：约 9.9 秒、一次生成、来源和历史一致；该配置关闭流式，所以本次没有首增量指标。深度规划的真实模型质量、真实联网效果和视觉仍未验证，也没有旧版本延迟对照。下一步测量更多模式，再建立中文检索标注集，引入经过评测的语义嵌入/重排及覆盖更完整的网页搜索服务。
